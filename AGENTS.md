# Правила проекта Dance&Friends

## Работа с репозиторием

- Не выполнять `git add`, не индексировать файлы и не изменять git index без явной просьбы пользователя сделать staging или commit
- Сохранять существующие пользовательские изменения и не откатывать файлы, не относящиеся к текущей задаче
- После изменений запускать `npm run build`, целевой ESLint для затронутых файлов и `git diff --check`
- Для локальных правок использовать существующие компоненты, стили и дизайн-токены проекта

## Общие правила интерфейса

- На каждой странице использовать общий header и footer
- Левый край заголовков всех внутренних страниц выравнивать по логотипу общего header: контейнер шириной `1180px` с горизонтальными отступами `24px` на десктопе и `16px` до `760px`; главная страница использует собственную композицию
- Основной фон сайта — `#F9F2E7`
- Насыщенный оранжевый цвет — `#F2A045`
- На оранжевом и других цветных фонах использовать белый текст
- Обычный белый текст на цветном фоне должен быть немного жирнее обычного, базовое значение — `font-weight: 500`
- В конце заголовков, абзацев, подписей, описаний и другого статического текста интерфейса не ставить точки
- Содержимое карточек и соседних блоков выравнивать по верхнему краю
- Блоки, расположенные в одной строке, делать одинаковой высоты, без произвольной фиксированной высоты
- Карточки и крупные блоки оформлять со скруглениями в стилистике сайта
- На мобильных многоколоночные блоки располагать друг под другом
- Цвет линди-хопа — красный
- Цвет блюза — голубой
- Цвет бальбоа — насыщенный оранжевый
- Как стрелки используй яркие символы `<` и `>` на круглой подложке, без белой тени

## Ассеты

- Обычные изображения брать из `src/assets/images`
- Фотографии преподавателей брать из `src/assets/teachers`
- Видео направлений брать из `src/assets/video`
- Иконки брать из `src/assets/icons`, не заменять их текстовыми обозначениями или самодельными иконками
- Иконки на цветном фоне делать белыми, без отдельной круглой подложки, обводки и белой тени

- Не использовать нумерацию направлений
- Видео показывать как галерею без внешнего фона, индикаторов и номеров
- Все видео в карточках должны иметь одинаковую высоту и заполнение области
- Стрелки галереи — яркие символы `<` и `>` на круглой подложке, без белой тени
- Заголовок и текст карточки направления выравнивать по верхнему краю
- Выделенные слова окрашивать в цвет соответствующего направления

## CTA

- Все CTA-блоки собирать через общий переиспользуемый компонент `CtaSection`, а сами ссылки — через `CtaList`
- Данные CTA загружать из листа `cta` настроенной Google-таблицы и кэшировать общий запрос между блоками
- Использовать колонки `label`, `link`, `text`, `color`, `metrica`
- `label` и `link` обязательны, остальные поля необязательны
- `color` принимает HEX-цвет и переопределяет только фон кнопки
- `metrica` содержит идентификатор JavaScript-цели Яндекс Метрики
- CTA со внешней ссылкой выводить как `<a>`, не открывать ссылку через обработчик кнопки
- Ошибка загрузки CTA не должна ломать расписание или остальную страницу
- В CTA сначала выводить все дополнительные тексты вертикально, затем кнопки
- Кнопки с первой до предпоследней по умолчанию чередовать между красной и насыщенной оранжевой; `color` может переопределить их фон
- Последнюю кнопку всегда делать прозрачной с белой обводкой, игнорируя `color`
- Только в первом CTA на главной кнопки располагать горизонтально под текстами
- Во всех остальных CTA заголовок и дополнительные тексты размещать слева, а кнопки — справа вертикальной колонкой; на мобильных складывать всё в одну колонку
- На десктопе делать группы CTA-кнопок шириной 80%: вне hero прижимать вправо, в hero — влево; на мобильных использовать полную ширину

## Мероприятия

- Мероприятия загружать из публичного Google Calendar, не из Google Sheets
- Calendar ID читать из `VITE_GOOGLE_CALENDAR_ID`, отдельный ключ — из `VITE_GOOGLE_CALENDAR_API_KEY` с fallback на `VITE_GOOGLE_SHEETS_API_KEY`
- Повторяющиеся события разворачивать в отдельные вхождения и загружать 12-месячное окно, начиная с текущего месяца Омска
- Дату и время брать из `start` и `end` события и форматировать в `Asia/Omsk`; all-day события подписывать «Весь день»
- Название брать из заголовка события, а описание разбирать как JSON с полями `type`, `text`, `buttons`
- События без JSON-объекта в описании, с некорректным JSON или без поддерживаемого `type` не отображать
- Перед разбором JSON очищать HTML-разметку, которую Google Calendar автоматически добавляет к переносам строк и ссылкам
- Лишние пробелы в данных события нормализовывать, сохраняя все намеренные переносы `\n` и пустые строки внутри `text`
- `type` обязателен и принимает `class` или `event`, `text` поддерживает выделение `*текст*` и `**текст**`
- Выделенный текст делать жирным и окрашивать в цвет типа мероприятия
- Описание и кнопки на десктопе показывать только при hover/focus, на мобильных — по нажатию на событие
- Если после загрузки или фильтрации событий нет, показывать пустой календарь текущего месяца и пустую текущую неделю на мобильных
- На мобильных группировать расписание по календарным неделям с понедельника по воскресенье
- На мобильных сначала показывать 6 недель и добавлять следующие 6 по кнопке «Загрузить ещё»
- На десктопе показывать компактную календарную сетку с пунктирными разделителями без скруглённых ячеек; в строке события выводить только время начала и название
- В начале hover-описания события на десктопе жирным выводить дату и полное время начала и окончания
- В `buttons` использовать `label`, `link`, необязательные `color` и `metrica`; некорректные кнопки пропускать
